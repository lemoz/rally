# TikTok Tech/Developer Content Trends Research
**Date:** April 8, 2026
**Purpose:** Inform Rally POC video style selection

---

## Executive Summary

Tech and developer content on TikTok is a large, active category. #programming has 6.2B views across 450K+ posts. #coding has 977K+ posts. The vibe coding / AI coding niche is exploding, with creators like Riley Brown (636K followers) and Sabrina Ramonov (731K followers) building large audiences around AI-assisted development.

The most critical finding: **authenticity beats production value**. Raw, phone-shot content with natural lighting sees 31% higher engagement than heavily edited studio content. The algorithm explicitly deprioritizes overproduced content because it triggers an "ad" response from viewers.

---

## Algorithm Context (2026)

Oracle now manages the US TikTok algorithm independently from ByteDance. Key signals:

| Signal | Weight | Notes |
|--------|--------|-------|
| Watch time + completion rate | ~70% | 70%+ completion triggers viral distribution. Below 70% rarely breaks 10K views. |
| Shares | 3x weight vs likes | Highest-quality endorsement signal |
| Saves | High | Especially valuable for educational content |
| Comments (thread depth) | Medium | Reply threads matter more than comment volume |
| Niche consistency | Critical | Creators posting 3+ unrelated topics see 45% lower reach |

**Distribution stages:**
1. Stage 1 (Hours 1-3): 200-500 non-followers matching the topic
2. Stage 2 (Hours 6-24): Performance evaluation against category benchmarks
3. Stage 3 (Days 1-3): Progressive audience expansion
4. Stage 4 (Ongoing): Top performers reach For You Page

**First hour is decisive.** ~60% of a video's total reach is determined in the first 6 hours.

## Video Formats That Work for Tech Content

### Format 1: Screen Recording + Talking Head Overlay

**What it looks like:**
- 9:16 vertical, 30fps
- Main area: screen recording of code editor, terminal, or app demo
- Small circular or rectangular talking-head cam in corner (typically bottom-left or top-right)
- Animated word-by-word captions across the middle/bottom
- Bold text overlays for key points

**Audio:** Direct voiceover (creator's real voice), no music or very low background lo-fi. Clear audio from phone mic or basic lav mic is sufficient.

**Hook (0-2s):** Show the finished result first. "I built this in 2 minutes" with the working app visible. Or start with terminal running, code flying by -- visual motion grabs attention.

**Duration:** 30-90 seconds. Sweet spot at 60s for tutorials.

**Who does this well:** Riley Brown (@rileybrown.ai, 636K followers, 8.9M likes). His vibe coding videos show building apps from scratch with Claude Code and Cursor. Example: "Build a video game in 2 minutes vibe coding. No coding required." Another: "Senior Vibe Coder built a mobile app from his phone and sent it to the app store in 4 minutes."

**Why it works for Rally:** This is the most natural format for showcasing open source projects. Screen recording of the project in action + voiceover explaining what it does.

---

### Format 2: Photo Carousel / Swipeable Slides

**What it looks like:**
- 1080x1920 static images (up to 35, sweet spot 5-15)
- Clean design: dark background, code snippets, diagrams, or screenshots per slide
- Bold headline text on each slide, minimal body text
- Consistent visual branding across slides
- Often paired with a trending or ambient audio track

**Audio:** Background music (trending sound or lo-fi). Sometimes voiceover narrating the slides.

**Hook (Slide 1):** Strong statement or question. "7 AI tools every developer needs in 2026" or "This open source project replaces 5 paid tools"

**Duration:** User-paced (swiping). Average dwell time is higher than video because users pause and re-read.

**Engagement pattern:** Carousels generate disproportionately high saves and comments. Each swipe extends dwell time, which the algorithm reads as high-value engagement. Currently underused relative to video, giving early adopters an advantage.

**Why it works for Rally:** Perfect for project discovery content -- one slide per project, or one slide per feature of a single project. Easy to produce at volume since it's static images + text.

---

### Format 3: Listicle / "X Things" Video

**What it looks like:**
- Talking head or voiceover + screen recordings
- Clear numbered structure: "5 AI tools you're sleeping on"
- Each item gets 5-10 seconds with a quick demo or screenshot
- Bold numbered text overlay for each item
- Fast cuts between items, visual variety per segment

**Audio:** Direct voiceover, energetic pacing. Some creators use slight background music.

**Hook (0-2s):** The number + topic. "5 free tools that replaced my entire paid stack" -- sets clear expectations for the viewer (they know exactly what they're getting).

**Duration:** 30-60 seconds for 3-5 items. Up to 90s for longer lists.

**Why it works for Rally:** Natural format for showcasing multiple open source projects in a single video. "5 open source projects you need to see" with quick demos of each.

---

### Format 4: Before/After Transformation

**What it looks like:**
- Split screen (top/bottom or left/right) or sequential reveal
- "Before": ugly UI, slow process, manual workflow, messy code
- "After": polished result, fast execution, clean output
- Text overlay: "This took me 10 minutes" or "From idea to app in 3 prompts"

**Audio:** Dramatic sound effect at the reveal. Trending audio that builds tension. Or simple voiceover explaining the transformation.

**Hook (0-2s):** Show the "after" first, then rewind. Front-load the impressive result.

**Duration:** 15-45 seconds. Shorter is better for this format.

**Why it works for Rally:** Ideal for AI coding tools, developer productivity projects, or any project where the output is visually impressive compared to the input effort.

---

### Format 5: Green Screen + Notes App / Text Reaction

**What it looks like:**
- Creator's face/upper body visible via green screen effect
- Background is a screenshot, code snippet, tweet, GitHub readme, or Notes app text
- Creator points at or reacts to the background content
- Sometimes the background scrolls through a thread or document

**Audio:** Creator speaking directly, often with a trending sound playing underneath. The speaking is the primary audio.

**Hook (0-2s):** Bold text or statement visible on the background. Creator's expression (surprise, excitement) acts as visual hook.

**Duration:** 15-60 seconds.

**Who does this:** Very common across all of tech TikTok. VS Code's official account (@vscode) uses this format for programming humor.

**Why it works for Rally:** Good for reaction content -- reacting to a project's features, stats, or capabilities. Low production cost.

---

### Format 6: Storytime / Direct-to-Camera Narrative

**What it looks like:**
- Creator speaking directly to camera, often handheld phone footage
- Minimal or no B-roll -- just face + natural background
- Animated captions word-by-word at bottom
- Sometimes a "Part 1 of X" series format

**Audio:** Creator's voice only. Natural, conversational tone. No music.

**Hook (0-2s):** Bold claim or surprising statement. "I made $14,000 last month from TikTok and I only have 3,000 followers" or "This AI tool is going to replace frontend engineers."

**Duration:** 60-180 seconds. Educational content creators push longer (up to 3 min) and TikTok rewards this if completion rate stays high.

**Engagement pattern:** Contrarian takes generate comment engagement, which fuels algorithmic distribution. Series content (cliffhangers) converts viewers to followers.

**Why it works for Rally:** Could work for "story of this project" narratives. Less applicable for volume production since it requires a consistent on-camera personality.

---

### Format 7: Companion / "Work With Me" Content

**What it looks like:**
- Lo-fi, cozy aesthetic
- Creator coding/working with screen visible
- Often time-lapsed or real-time with ambient audio
- Minimal narration -- the appeal is "hanging out" with someone while they work

**Audio:** Lo-fi music, keyboard sounds, ambient coding. Minimal talking.

**Hook:** The aesthetic itself. Cozy desk setup, nice lighting, satisfying keyboard sounds.

**Duration:** 60 seconds to 3+ minutes. Longer formats work here because the content is designed as background.

**Why it works for Rally:** Limited applicability for project promotion, but could be used as a style variant -- "watch me build X from scratch" in 60 seconds.

## Hook Formulas That Work for Tech Content

### The Curiosity Gap
"I found an AI tool that does [impressive thing] and nobody is talking about it"
- Creates information need that can only be satisfied by watching

### The Bold Claim
"Open source is about to kill [paid product]"
- Challenges conventional wisdom, drives comments (debate = engagement)

### The Speed Claim
"I built this entire app in 2 prompts" / "This took me 10 minutes"
- Time-based claims create immediate intrigue

### The Discovery Frame
"5 tools/projects you're sleeping on"
- Implies insider knowledge the viewer is missing

### The Pattern Interrupt
- Visual: Something unexpected in frame (code running impossibly fast, dramatic before/after)
- Show the result first, then explain how

### The Direct Question
"Why are developers still doing [thing] manually?"
- Activates internal monologue, viewer needs to know the answer

**Critical metric:** 63% of highest-CTR videos hook within 3 seconds. Videos with >65% 3-second retention get 4-7x more impressions.

## Audio Patterns

1. **Direct voiceover (most common for tech):** Creator narrates in natural voice. No fancy mic needed. Conversational, slightly energetic tone.
2. **TTS voice:** Less common in 2026 than 2023-2024. Used mainly for meme/humor content. The algorithm now weighs content quality signals over sound selection.
3. **Trending sounds + text overlay:** Audio from trending track, all information delivered via on-screen text and visuals. Works for carousels and transformation content.
4. **Lo-fi / ambient:** Background music for companion content. Keyboard ASMR for coding content.
5. **No audio / captions only:** Many viewers watch on mute initially. The hook must work visually first. Animated word-by-word captions are now table-stakes.

## Technical Specs

- **Resolution:** 1080x1920 (9:16 vertical)
- **FPS:** 30fps for talking head/slideshow, 60fps for fast screen recordings
- **Format:** MP4
- **Captions:** Animated, word-by-word, bold. Tools like CapCut and Captions App auto-generate these.
- **Length sweet spots:** 15-30s (quick hits), 30-60s (tutorials/listicles), 60-180s (deep educational)
- **Posting cadence:** 1-3x daily for growth. Minimum 3-5x weekly.

## Recommendations for Rally POC

### Priority Formats (easiest to produce with AI, highest engagement potential):

1. **Photo Carousel** -- Static slides are trivially producible, high save rates, educational content is the dominant use case. Start here for volume.

2. **Screen Recording + Voiceover** -- Capture project demos, add TTS voiceover, layer captions. No human face needed. Straightforward to automate.

3. **Before/After Transformation** -- Two states with a dramatic reveal. Simple structure, high impact. "Your workflow before [project] vs after."

4. **Listicle Compilation** -- "5 open source projects that..." with quick cuts between screen recordings. Can batch-produce from a library of project demos.

### Deprioritize for POC:
- Talking head (requires consistent human personality)
- Companion content (low promotional value)
- Storytime (hard to automate, requires personality)

### Hook Templates for Open Source Projects:
- "This open source project just replaced [paid tool]"
- "I found an AI tool that [impressive capability] and it's completely free"
- "Stop paying for [category]. Use this instead."
- "[Number] open source projects that will blow your mind"
- "Watch me [accomplish task] in [short time] with [project name]"
- "Nobody is talking about this open source [category]"

### Production Notes:
- Raw > polished. Phone-quality is ideal.
- Animated captions are mandatory (not optional).
- Show the result in the first 2 seconds, explain after.
- Each video needs a clear "save-worthy" moment (the algorithm now weighs saves heavily).
- Batch produce: script 7-14 videos in one session, produce all at once.
